# 生产者 - 消费者集成测试使用说明

## 📋 测试概述

本测试模拟真实生产环境的数据迁移场景：

1. **A 库（unit-01）**: 源数据库，包含原始数据
2. **B 库（unit-02）**: 目标数据库，接收迁移数据
3. **生产者**: 按天分批查询 A 库 + RocksDB 去重过滤
4. **消费者**: 从队列获取数据并批量插入 B 库

---

## 🎯 核心功能

### 1. 数据库表创建
- ✅ A 库源表 `source_data`（原始结构）
- ✅ B 库目标表 `target_data`（增加迁移标识字段）
- ✅ 两表结构略有差异，符合生产场景

### 2. 测试数据初始化
- ✅ 按时间范围生成数据（格式：yyyy-MM-dd HH:mm:ss）
- ✅ 可配置每天数据量
- ✅ 可配置重复率（模拟 B 库已有数据）

### 3. 生产者功能
- ✅ 按天分批查询 A 库数据
- ✅ 使用 RocksDB 过滤器去重
- ✅ 将数据放入阻塞队列

### 4. 消费者功能
- ✅ 从队列获取数据
- ✅ 批量插入到 B 库
- ✅ 添加迁移标识和时间戳

## 🔍 核心流程解析

### 1. 数据库表结构对比

#### A 库源表（source_data）
```sql
CREATE TABLE source_data (
  id bigint(20),              -- 主键
  business_time datetime,     -- 业务时间
  user_code varchar(50),      -- 用户编码（去重关键字）
  user_name varchar(100),     -- 用户姓名
  amount decimal(10,2),       -- 金额
  status int(11),             -- 状态
  remark varchar(500),        -- 备注
  create_time datetime,       -- 创建时间
  update_time datetime        -- 更新时间
);
```

#### B 库目标表（target_data）
```sql
CREATE TABLE target_data (
  id bigint(20),              -- 主键
  business_time datetime,     -- 业务时间
  user_code varchar(50),      -- 用户编码（UNIQUE KEY）
  user_name varchar(100),     -- 用户姓名
  amount decimal(10,2),       -- 金额
  status int(11),             -- 状态
  remark varchar(500),        -- 备注
  source_flag varchar(50),    -- ✨ 来源标识（新增）
  migrate_time datetime,      -- ✨ 迁移时间（新增）
  create_time datetime,       -- 创建时间
  update_time datetime        -- 更新时间
);
```

**差异说明**:
- B 库增加了 `source_flag` 字段（标识数据来源）
- B 库增加了 `migrate_time` 字段（记录迁移时间）
- B 库对 `user_code` 有 UNIQUE 约束（防止重复）

### 2. 数据初始化流程

```
DatabaseInitializer
  ↓
1. createSourceTable()    → A 库创建 source_data
2. createTargetTable()    → B 库创建 target_data
3. initTestData()         → 生成测试数据
   ├─ generateDateList()      → 生成日期列表
   └─ for each date:
       ├─ generateDailyData() → 生成当天数据
       │  ├─ ID（全局唯一）
       │  ├─ business_time（随机时分秒）
       │  ├─ user_code（根据重复率决定是否重复）
       │  └─ 其他字段（随机值）
       └─ batchInsertToSource() → 批量插入 A 库
```

**重复数据生成逻辑**:
```java
if (duplicateRate > 0 && i < count * duplicateRate) {
    // 重复数据：使用已存在的 user_code
    userCode = "USER_" + String.format("%08d", (i % baseIndex) + 1);
} else {
    // 新数据：生成新的 user_code
    userCode = "USER_" + String.format("%08d", id);
}
```

### 3. 生产者 - 消费者流程

```
┌─────────────┐         ┌──────────────┐         ┌─────────────┐
│  生产者线程  │ ──────→ │ BlockingQueue│ ──────→ │  消费者线程  │
│             │         │   (容量 10)    │         │             │
└─────────────┘         └──────────────┘         └─────────────┘
     ↓                          ↓                        ↓
按天查询 A 库                   阻塞                      从队列获取
RocksDB 去重                                         批量插入 B 库
```

#### 生产者详细流程

```java
for (Date businessDate : dateList) {
    // 按天循环
    
    offset = 0
    while (true) {
        // 1. 查询一批数据
        SELECT * FROM source_data 
        WHERE DATE(business_time) = DATE(?) 
        ORDER BY id 
        LIMIT 5000 OFFSET ?
        
        // 2. RocksDB 去重
        filteredData = duplicateFilter.filterDuplicates(dataList)
        
        // 3. 放入队列（可能阻塞）
        dataQueue.put(filteredData)
        
        offset += batchSize
    }
}
```

#### 消费者详细流程

```java
while (!stopFlag.get()) {
    // 1. 从队列获取数据（阻塞最多 1 秒）
    dataList = dataQueue.poll(1, TimeUnit.SECONDS)
    
    if (dataList != null && !dataList.isEmpty()) {
        // 2. 批量插入 B 库
        INSERT INTO target_data 
        (id, business_time, user_code, ..., source_flag, migrate_time) 
        VALUES (?, ?, ?, ...)
        
        // 3. 更新计数
        consumedCount++
    }
}
```

## 📈 性能监控

### 关键指标

测试过程中会输出以下指标：

1. **A 库总数据量**: 源数据总数
2. **B 库总数据量**: 迁移后数据总数
3. **生产者产出**: 去重后的数据量
4. **消费者消费**: 实际入库的数据量
5. **过滤器去重**: 被过滤的重复数据量

### 性能参考

| 数据量 | 预计耗时 | 处理速度 |
|--------|---------|---------|
| 7 万条 | ~30 秒 | ~2300 条/秒 |
| 70 万条 | ~5 分钟 | ~2300 条/秒 |
| 700 万条 | ~50 分钟 | ~2300 条/秒 |

**注意**: 实际速度取决于：
- 数据库性能
- 网络延迟
- 批次大小配置
- RocksDB 性能
